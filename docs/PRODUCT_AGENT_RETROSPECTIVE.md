# 从记分器到围桌：产品与 Agent 协作复盘

围桌的主要目的，是用一个真实可用的产品观察和验证 Agent 的开发过程，同时锻炼人的产品判断、规则推演、逻辑思维和验收能力。让线下桌游记分方便，是这些思考的实际落点。

这不是“给 Agent 一句话，它就自动完成产品”的展示。许多关键改进来自作者 Snowdar 的现场观察、截图反馈和取舍：人在提出问题、决定体验与验证结果；Agent 主要承担架构、实现、调研和检查。生成场景由 GPT Image 提供，但一个好看的场景并不自动成为好用的界面。

本文根据本项目的开发对话整理，按问题演进归纳，而不是逐条聊天日志或精确日期的版本历史。涉及已经实现、验证范围有限和仍在规划的工作，会分别说明。可执行的开发要求见 [AGENTS.md](../AGENTS.md)，当前使用和安装见 [README](../README.md)。

## 1. 从“能记分”到“能重新找到自己”

起初最容易关注的是创建房间、加入和记分。实际使用暴露了更基础的问题：房主关闭网页再回来，找不到自己的房间；玩家重新扫码后，成了另一个人。

人的贡献是重新定义身份：关闭页面不等于退出，昵称不等于身份，扫码邀请也不等于恢复原玩家。随后又提出，大厅应直接展示“我参与的房间”，让重进路径清晰，而不要求人记住房间码。

实现因此增加了设备身份、服务端身份与房间绑定、个人身份二维码、持久化房间和主动离开按钮。邀请二维码与身份二维码分开：前者邀请入房，后者恢复本人。默认昵称是便利，重名补字母用于显示区分，不能替代身份凭证。

**留下的判断方法：**先问“关掉页面再回来会怎样”，再问“当前页面有几个功能”。必须把刷新、关页、返回大厅、离开座位、销毁房间和删除数据区分开。设备身份依赖保存的凭证，不能承诺清空浏览器后仍无条件恢复。

## 2. 从按钮面板到人的操作路径

最初的页面把邀请、身份、改名、规则、离开和公屏并列放置。功能齐全，但入口占据大量首屏空间，同一玩家信息又重复出现在奖池和下方列表。

作者逐次指出：公屏去掉；身份和改名收进用户名入口；规则靠近游戏信息；房间号、游戏名、局数统一排在房间名下面；邀请使用图标；控制台不要再重复全员列表。

这些并非单纯“调字号”。它们改变了信息的组织方式：持续需要的信息直接显示，临时想看的信息按需打开；对象本身成为操作入口。点击玩家管理玩家，点击奖池处理奖池，而不是先寻找一排同义按钮。

**留下的判断方法：**入口应回答“我要操作谁、在哪里点”，并让首次扫码的人尽快完成一次操作。去掉重复信息比继续缩小字号更有效。

## 3. 德州扑克把“记分”变成“流程助手”

德州扑克的难点不只是加减积分，还包括盲注、全下、未被跟注投入退还、主池与边池资格、平分以及线下发牌顺序。

作者提出，记分器也应是庄家的帮手，且庄家可以同时是玩家。于是需要把“本人行动”和“发牌协助”分开，向全员显示等待助手、发牌阶段与当前行动进度；现实发牌要明确先给谁，并提示烧牌等步骤。

房主最终选择赢家也被改为直接点击有资格的角色卡片，再结算；弃牌者不得选择，预选赢家同步给其他人，预选和实际派奖使用不同状态。后台仍须校验资格与金额，不能把权限交给视觉高亮。

**人的思考贡献：**将复杂规则翻译成主持人此时需要知道的下一步，而不是把规则术语全部堆在界面上。Agent 可以调研和实现，但现场流程、谁能代办、何时应该提醒，仍需要人确定。

## 4. 从长网页到固定视野的牌桌

手机竖屏让普通网页布局的缺点变得明显：信息、操作和玩家散布在页面不同位置，需要来回上下滑。作者要求主页面固定，自己始终在底部，操作尽量靠近自己的卡片，复杂行动放中央空白区。

接着出现更细的反馈：卡片有的在桌内、有的在边缘；上下三张不对称；编号随布局重复；中央奖池偏移；操作覆盖玩家；背景露出第三层纯色。每一轮截图都在校正空间关系。

由此形成：按人数自动布局、按观看者旋转座位、玩家编号跟随身份、拖动只交换顺序、沿桌沿对称布置、中央动作避让实际卡片边界、横屏单独构图。场景也从分离背景改为桌子与环境一体。

**踩过的坑：**固定 `100vh` 不代表手机真实可见高度；缩放整张桌子不代表可读；面板外框没有重叠，不代表按钮内部没有溢出。布局需要考虑浏览器工具栏、键盘、方向、长昵称和人数，而不是只在电脑截图上成立。

## 5. 动画必须解释状态，不应挤占操作

筹码投入与派奖动画来自作者希望看清积分流向、让奖池随金额增长呈现变化的想法。随后又要求，按钮与消息分开，不共用一层大背景；短按钮不应拉成长条，留白不等于大片空白。

这些反馈把视觉效果限制在实际使用的范围内：筹码规模可以变化，占用区域应稳定；投分和派奖不能因每秒轮询重复播放；尊重减少动态效果偏好；视觉不能替代金额和成交记录。

**留下的判断方法：**每个效果都应能解释“发生了什么”。先确保玩家看得清、点得到，再考虑场景氛围。

## 6. 自由记分不必继承扑克的复杂度

把牌桌设计复用到自由记分后，作者发现卡片重复写“自由积分”“点击给分”，操作过重。需求又从单向赠送扩展到请求收取、全场多人交换、可编辑并收藏的规则，以及可选奖金池。

关键取舍是：自由记分允许负分，奖金池默认关闭；玩家可选参与全场操作的人，默认所有其他人；给出直接执行，收取必须由对方确认、可拒绝、发送者可取消。早期曾要求给出二次确认，后来又根据操作效率明确取消，这是产品判断随使用反馈更新的实例。

最终自由记分默认简约列表，牌桌作为个人可切换外观，两种视图共用数据、权限和动作。简约列表优先显示名字与分数，成交记录独立滚动。操作名称最终确定为“给出 / 收取”，记录用“甲给了乙 10 分 / 甲收了乙的 10 分”，姓名分色，金额黑色加粗。

**人的思考贡献：**发现不同游戏的核心任务不同，并敢于收回已经投入视觉成本的方案。默认值是产品选择：默认简约、默认无奖池、默认每人 1 分，都在减少首次理解成本。

## 7. 从“截图通过”到真正的手机触摸

这是本项目特别值得保留的失败经验。

简约列表曾在悬停时突然变宽，原因是共享牌桌 hover 规则的优先级覆盖了列表内边距。修复后需要保证悬停只改变鼠标可见反馈，不改变宽高、位置或内边距，触摸不保留悬停选中。

记录窗口又出现覆盖玩家、看似不能滚动的问题。首先发现，玩家区沿用牌桌整高设置，没有为新增记录区分配剩余高度。修复分区后，电脑滚轮正常，但作者实机仍反馈手指滑不动。

后续才找到手机特有原因：锁定全页的 `touchmove` 拦截没有允许新增的简约玩家区与记录窗口。**鼠标滚轮能动、模拟手机尺寸的截图正常，都不能证明真实触摸手势正常。** 此外，手指按住或惯性滚动期间重建 DOM，可能打断操作，因此需延后重绘，停止后再展示最新状态。

长按复制也需要按对象区分：按钮、玩家卡片、菜单入口禁止选择与系统菜单；成交、下注和动态记录允许复制，编辑输入仍可选字。不能为修一处长按行为，把整页触摸或文本复制都禁掉。

**当前证据边界：**浏览器尺寸检查和触摸事件回归已补充；这些不是所有 iPhone / 安卓浏览器的实机认证。人的真实反馈仍是必要验收输入。

## 8. 联网、资产与数据保护也是体验

服务熄屏后卡住、没有网络等待或失败提示，说明“局域网”也不等于稳定连接。图像素材过大还会放大首屏和弱网络等待。

改进包括公开素材压缩为 WebP、合理缓存与脚本重验证、合并并发读取、后台暂停同步、前台恢复同步、提交等待与超时提示。状态和身份接口不缓存。积分动作不能因超时自动反复发送，应先查记录确认结果，再继续操作。

作者多次明确，重启必须保留当前牌局与积分。于是正式房间与测试空间隔离，重启先审计并备份，旧快照兼容迁移，禁止用清库解决问题。房间数据保存在服务设备，持久保存不等于服务永久在线。

**留下的判断方法：**网络失败时人应该知道下一步做什么；后台实现正确，也要在界面上可理解。

## 9. 平台选择先问谁承担成本

讨论过局域网网页、小程序、云开发，以及手机房主主持。作者关注服务器、HTTPS 和后续维护成本，也希望摆脱本地电脑，但暂不做热点，先考虑同 Wi-Fi 的安卓与 iPhone App。

这里的产品贡献是明确部署姿势：谁启动、谁扫码、数据在哪、主机退出时大家怎么办。不能将有移动工程等同于已有可安装包，也不能将客户端消息排队等同于 iOS 后台仍能运行服务。

iPhone 已完成个人签名安装、启动服务、本机大厅与同 Wi-Fi HTTP 接入的初步实机验证。后续服务首页和折叠返回入口通过构建及流程检查，仍需补充实机视觉验收；安卓尚未完成真机验证。文档应据实际证据声明支持，不用“工程已有”替代“设备已验证”。

## 人需要提供的思考，不只是功能清单

| 人的贡献 | 本项目中的例子 | Agent 应产出的工作 |
| --- | --- | --- |
| 使用场景与姿势 | 手机竖屏、现实发牌、关闭网页后回来 | 实现可恢复状态，测试视口与流程 |
| 规则边界 | 弃牌不能赢对应池、房主默认准备、是否允许负分 | 服务端校验、兼容旧房间、回归规则 |
| 优先级与默认值 | 自由记分默认简约、奖金池默认关闭 | 共用业务逻辑，减少多套实现 |
| 视觉判断 | 对称桌沿、按钮短、文字不透视、提示分层 | 布局避让、素材适配、截图核对 |
| 操作成本 | 直接点玩家、收取可取消、直接给出 | 权限与去重、持久请求状态、失败保留 |
| 真实验收与纠错 | 手机滑不动但电脑正常 | 找到触摸拦截原因，补事件测试 |
| 分发与用途边界 | 非商用、不能作为赌博载体 | 统一许可、第三方说明与发布元数据 |

Agent 也应主动提出问题、指出限制并做自查；不能把每一个缺陷都留给人发现。人的贡献不要求写代码，但需要把“这里很怪”逐步落实为场景、预期、取舍和可验证行为。Agent 的责任则是把这些判断落成可靠实现，而不是用“已修复”的文字代替证据。

## 如何继续积累这份价值

每个有价值的迭代都可以留下五项内容：真实场景、错误表现、人的判断、最终实现、验证与未覆盖范围。产品复盘记录原因和变化，AGENTS.md 只保存后续仍适用的操作约束，CHANGELOG 记录最终功能。

旧判断被新决定替代时，应更新原约束，不继续堆叠互相矛盾的段落。测试数据、身份凭证和完整私人对话不属于复盘素材。图片注明是生成素材还是运行截图；测试注明是规则测试、浏览器视口还是实体设备。

围桌的成果不只有一个记分应用，也包括如何识别真实需求、减少操作负担、用反例推演逻辑，以及如何让 Agent 在人的判断和证据约束下持续改进。

## 实机白屏与排障成本

一次 iPhone 输入布局更新后，已有安装的手机启动白屏，而干净模拟器可以完成启动。最初的原生日志只显示语音模型已加载，缺少 Python 启动异常；仅检查窗口尺寸没有找到原因。增加应用自身的启动诊断文件后，实机堆栈指出音色偏好读取失败：`NSUserDefaults.objectForKey` 返回的是 `NSNumber` 代理，直接 `int()` 转换会抛出异常。首页尚未创建，问题与牌桌背景和输入面板的位置无关。

修复改用原生整数访问器，无效偏好回退默认值，并补充已有设置的回归用例。build 19 保留用户数据安装到 iPhone 16 后，诊断确认首页创建、窗口可见，用户确认首页恢复正常。键盘输入的验收是下一条独立路径，不能从首页恢复推断键盘问题也已解决。

这几轮处理慢，既有热点与 VPN 环境下开发工具连接中断、审批等待和手机锁定造成的外部阻碍，也有排障方法上的不足：没有尽早拿到实机 Python 异常；干净模拟器缺少旧设置这个反例；将构建成功、模型加载成功与界面可用混在了一起。后两类是 Agent 应改进的工作，不能归咎于网络。应先把问题缩小到启动、窗口、网页加载或输入的具体阶段，再做针对性改动；每轮分发增加构建号，并保留失败现场和验证范围，减少盲目重装。

随后又出现一次交付疏漏：仅运行 Briefcase 更新原生工程，没有先收集新网页资源，导致新构建号的安装包仍包含旧输入布局。用户截图中仍有旧的两行按钮，比“源码已改”和“构建成功”更直接地揭示了问题。现在 iOS 配置步骤校验仓库源码、暂存资源和 Xcode 工程的内容与版本，分发前核对最终安装包；资源不一致时阻止继续配置。构建流水线的可复现性也是功能正确性的一部分。

## 记录阅读与演示验证

记录的价值是让人核对发生了什么。人的选择是统一从早到新、时间前置、姓名与动作区分颜色，并在有限窗口里自然滑动到最新；上翻阅读时不能被轮询拉回底部。这要求 Agent 同时检查数据顺序、显示顺序、触摸滚动和重绘，不能只把数组反转后就认为完成。房间动态的后台存储是最新在前，展示反转插入顺序；只按时分秒排序会在跨午夜和同秒事件中出错。

展示产品也属于验证：创建房间前展示身份与玩法入口，用三个独立玩家完成真实的一局，才能看见准备人数、发牌协助、玩家行动、赢家同步选择和实际派奖是否衔接。演示使用隔离的虚构数据并遮蔽个人身份凭证，录屏不是 AI 概念图，也不能替代实体手机上的触摸、键盘和前后台验证。README 应告诉观看者视频展示了什么，开发约定保存这些验证边界。

## 离线声音：试听是产品验收，脚本也需要质量门槛

声音从系统音色、轻量 VITS 到 Serena 预制片段的取舍，首先来自人的听感与资源要求：需要年轻、自然、收音完整，又不能把大型生成模型装进服务手机。固定编号取代昵称播报，使多个音色共用一致文本，同时解决昵称读音和拼接资源规模问题。

后续的“行动拖长”“分字弱”“连续弃牌接结算漏报”和“下注被念成押上”分别属于素材质量、发音、队列完整性和术语准确性，不能都归因于同一层。对原始 WAV 测量发现，个别数字与动作素材长至十余秒；只听几句好样本无法证明整库合格。用户提供另一轮已试听优化的结果，促使开发将多候选生成、时长门槛、收音提示、弱辅音保护及整句验收固化，而不是继续盲目调整播放间隔。

留下的约束是：术语与按钮一致，素材质量与播放性能分开；生成、工程更新、包内资源和实机验证分别留证据。质量报告记录候选和处理方式，时长通过不冒充文字识别或人工试听通过。软件、模型、音色和生成音频的来源也分别记录；引擎许可不能替代训练数据或音色授权。


### Serena 拼接的经验：上下文比接缝技巧更重要

- **先拆分问题，再选修复层。** “轮到”拉长可能来自完整原录音；“一百”吞字可能来自切点；不同金额声线跳变可能来自不同生成批次；弃牌后漏结算则属于事件和队列。先保存原句、切片、最终运行 WAV 与播放顺序，分别对照，不能一律靠调整静音修复。
- **人的算法引导决定方向。** 作者提出“原句模板抠槽、同模板整句抠变量”，把优化从孤立字词合成转向上下文保留。Agent 将其落实为整句优先、金额与“分”整段、句中编号与句尾金额分组，以及按模板限制可用组合。完整句内部没有接缝，应优先复用；有限模板配对不等于任意变量都已验证。
- **同一音色名称与同一提示词不保证声线一致。** 分批录制的重音、气声、句末语调仍会变化。以实际采纳的录音作为对照，统一平静、端正、饱满、中等而利落的语气；先录同上下文完整句，必要时连续录制流程，再保守提取句界。语速按人耳反馈校准，不用全局变速或移调掩盖素材问题。
- **对齐时间戳只是候选边界。** 回查原句、低能量区与轻辅音，切点不可落在强音内部。没有安全边界就扩大上下文或保留整句；相邻未处理切片应逐样本还原原录音。裁边、响度处理和极短去点击包络分别留证，不能用跨淡化覆盖字头，也不能仅凭波形平滑断言不吞音。
- **评审最终播放句，而不是只评审素材。** 前缀与金额分别好听，组合后仍可能不自然。模板只开放明确审查的配对，从实际事件生成器和共享播放规划器导出整句，覆盖自由给分、请求发送与确认、炸金花，以及德州开局、各街发牌、行动、All-in、边界金额和连续结算。
- **模型筛选与人耳判断各有边界。** dots 先盲转写，再核对文字、连续性、饱满度、音色和普通话咬字；识别正确仍可能有外语腔。用户指出“轮到二号玩家行动”的口音后，即使旧评分通过，也要重录完整句。相同音频哈希与相同目标／标准可复用证据；接口格式错误只算审核未完成，不反复提交未改变的成功结果直到得到高分。
- **覆盖、听感与设备播放分开验收。** 4,391 项覆盖说明能生成所需文件，不代表所有金额都经人耳试听。检查需区分候选、模型初筛、按授权标准采用和逐句人耳采纳；新候选尚未收到反馈时明确保留这一状态。打包后核对正式 manifest、WAV 与版本，再验证目标设备的队列、提示铃、静音和完整句播放。
- **保留可追溯证据，控制发布体积。** 记录原句、模型修订、提示词、种子、切点、处理方法、最终哈希与替换关系。只打包正式 manifest 引用的资源，开发候选和 Qwen 权重不进入客户端；代码、推理引擎、模型、音色与生成音频分别说明来源及许可。当前公共源码不包含本地模型和声音库。

实现与各批次验收范围见 [TTS 音频评审](TTS_AUDIO_REVIEW.md)，复现和端侧延迟见 [离线语音](OFFLINE_VOICE.md)。这些方法改善了已检查的句子，不构成对任意拼接组合自然度的保证。

### 安卓实机网络检测：桥接调用不能只靠 Python mock 验证

Mate 60 的实机日志显示，初版闪退来自 Chaquopy 直接调用 `java.util.Enumeration.nextElement` 时抛出“abstract and cannot be called”。后续异常保护虽然允许首页打开，却仍没有取得 IP；Python mock 只模拟普通方法，不能证明厂商 Java 桥接工作正常。USB 调试授权后，系统接口明确显示 wlan0 的 IPv4，而应用为空，证据将问题收敛到 Java 枚举调用。

修复将 Enumeration 交给 Java 的 Collections.list 处理后转为数组，Python 仅遍历结果，回归覆盖直接 nextElement 不可调用的情况。build 34 保留数据安装到 Mate 60，应用自身启动诊断确认检测到与系统一致的 Wi-Fi 地址；这验证启动和地址发现，不代表热点、长时间主持或所有安卓交互均通过。开发者模式不等于 USB 调试授权；排查需先确认设备实际连接，再读取应用所属进程与当前构建日志，不能把历史日志或安装成功当作修复证据。

## 四端播报与端到端验证（2026-10-07）

- 人提出的约束：手机和桌面应有相同的四音色、试听与播报功能；Mac、Windows 可以省略热点功能。
- Android 使用官方 sherpa-onnx 1.13.8 AAR、同一 FP16 权重模型及 Serena 素材，后台生成、AudioTrack 顺序播放。Mate 60 男女声与 Serena 已实际试听确认。
- 桌面模型在服务设备本地生成 WAV，Serena 共用上下文规划器并保留采样，浏览器承担播放；接口检查同源、服务设备与房主凭证。Windows 接入同一代码，仍待目标系统验收。

## 牌桌场景与卡片定位必须使用同一坐标系

- 录制回看暴露了视觉检查遗漏：三人德州没有正上方角色，记录误占上方木质桌沿；炸金花和自由记分的上下角色在全屏后深入桌布，失去对称。
- 原因是背景依照整个布局容器渲染，座位却按另一个内容表面的百分比定位；原生安全区再给表面增加 padding，进一步扩大错位。只检查卡片是否越界，无法发现卡片与桌图是否一致。
- 修正方式是为各场景标定真实桌沿，按背景 stretch/cover 与裁切偏移统一投影；卡片、记录和桌图同步适配。记录区域整体居中，时间列与正文仍左对齐；避让范围包括独立定位的奖池文字和筹码。
- 回归覆盖三种游戏的二人、十人夹具，普通／沉浸视图，以及约 393×852、320×568、852×393、1280×720 的实际浏览器尺寸；另检查 62px 顶部安全区的样式。实际读到的尺寸可能受浏览器缩放取整，不以配置值替代测量值。
- 这轮是浏览器 DOM、尺寸和视觉检查，并非实体 iPhone 的安装／键盘验收。后续展示录制必须使用修复后的布局，不继续复用已知错位的旧画面。

### iPhone 服务页网络地址与键盘退出

- 实机接口日志显示 Wi-Fi en0 分配 172.40.4.86；局域网并不一定采用 RFC1918 私有地址。旧发现与服务校验均以 is_private 过滤，导致空白与手动填写被拒绝。发现按本地 Wi-Fi/热点接口选择有效单播 IPv4；非私有地址启动额外核对是否确属本机接口，排除蜂窝、VPN 与随意填写的公网地址。
- 服务首页启动立即显示检测结果，无地址明确提示；网络接口变化写入应用诊断，便于实机排查，不做公网探测。
- 原生 IP 输入配有“完成”键盘工具栏，点击连接方式或启动服务也解除输入响应者；不复用网页下注的键盘停靠布局。

- 网络模式跟随实际接口：Wi-Fi 稳定消失后切换本机热点并禁用 Wi-Fi 选项；重新连接则恢复可选。热点未开启只提示设置，不伪造地址或自动重启服务。监测同时比较 Wi-Fi 与热点地址，避免选中热点时忽略 Wi-Fi 恢复；连续两次一致后更新以避免切换抖动。


### 网络模式审计：不能用 Wi-Fi 地址冒充热点地址

- build 44 仍沿用“热点接口优先、缺失时用 Wi-Fi”的旧兜底，导致两个模式显示相同地址并把尚未开启的热点误报为可用。此次移除兜底：同一 Wi-Fi 仅取客户端接口，本机热点仅取热点/桥接接口；无接口显示“尚未检测到可用接口”并禁止启动，而不是宣称系统热点已经关闭或已经开启。选择热点模式本身不改变系统设置。
- 网络重启提示同时比较模式与地址，即使地址恰好相同也不能忽略模式变更。启动前重新检查选定网络，防止监测稳定等待期间使用已经失效的地址；检测变化不停止现有服务或改写当前邀请地址。
- Android 共享网络发现与服务 UI，旧 APK 同样可能受热点回退影响；厂商热点接口名不确定时不猜测、不用 Wi-Fi 冒充，需真机验证。Mac/Windows 不提供本机热点模式，但启动地址校验仍拒绝非私有 IPv4；桌面已改为对非私有地址验证本机 socket 可绑定性。iPhone UITextField 键盘完成入口为原生 iOS 专属，桌面输入并不采用此键盘布局。
- 验证包括两模式独立地址、热点未就绪禁用启动、模式变更同 IP 仍提示重启、网络连续观测、接口地址校验。源码检查不等同于 Mac/Windows/Android 新包已构建或目标设备已验证。

- 网络变化提醒覆盖原生服务首页与宿主大厅/牌桌：导航展开提示返回重启并让玩家重新扫码，同一提示不随每轮桥接强制重开；重启完成另提示重新分享当前二维码。桌面首页同样明确重扫。提示不自动中断服务或清空房间。


### 局域网自测与 Wi-Fi 隔离：避免错误证明

- 用户反馈部分 Wi-Fi 本机能开服务但其他设备连不上。单机访问自身 LAN IP 走本机协议栈，不能作为 AP 不隔离、另一台设备可达的证据；实现分层诊断而非宣称自动检测隔离。
- 共用服务提供服务机专属连接检查：两次 2 秒上限的 HTTP 自测分别访问回环与配置的邀请 IP，禁用 HTTP 环境代理，并核对当前服务实例随机标识，避免另一个围桌实例误报通过。仅请求固定的本机服务端口，不扫描网段。
- 第二阶段生成 3 分钟有效的随机诊断二维码，由另一设备访问；只按 TCP 对端识别外部访问，不信任转发请求头。服务机访问自身地址不作为远端成功。状态及二维码仅服务机可读，最多 8 个内存会话；到期和换地址后失效，不持久化客户端 IP。
- 已收到另一设备访问仅证明那台设备到当前服务的链路可用；未收到不能直接归因为隔离，UI 提示访客网络、客户端隔离、防火墙、VPN、权限与网络地址等排查项。
- 新增真实 HTTP 回归覆盖自测成功不等于远端、模拟 TCP 对端访问、权限隔离、到期、换网、测试空间、代理禁用和实例校验；浏览器 393×852、320×568、1280×720 检查无横向溢出，短屏弹窗自身滚动。未验证真实路由器隔离，也未宣称新版安装包已构建或安装。

# 架构说明

浏览器 → `weizhuo/server.py` HTTP → `weizhuo/scoring/rooms.py` 权限及动作处理 → 游戏规则 → `weizhuo/scoring/repository.py` SQLite 快照。

Rooms 使用锁保护操作，负责权限、版本及重复请求；服务端校验规则并持久化。前端原生 HTML/CSS/JavaScript，无构建步骤，通过轮询刷新，不使用 WebSocket。

游戏注册表统一提供炸金花、德州扑克和自由记分；新增游戏进入可搜索、可分类的目录。德州引擎独立处理每轮投入、加注权、未跟注退回、底池资格和整数派奖；庄位与操作流程协助者分开。`mahjong` 标识保留，显示名改为自由记分。

主要接口：`GET /api/bootstrap`、`GET /api/state`、`POST /api/rooms`、`POST /api/action`、`POST /api/device`。管理员接口、房间邀请二维码和大厅身份二维码独立；身份二维码携带设备凭证的 URL 片段，访问后绑定同一设备身份并恢复全部关联房间。德州关键动作附带状态版本，避免轮询期间旧页面误操作；`/test/` 使用测试库。

数据库保存房间快照和结算，兼容旧单房间状态，令牌和设备映射属于敏感数据。存储变化需验证旧快照、隔离、积分守恒和重复提交。

当前目标是单机单进程局域网使用，不应启动多个服务进程共写数据库。运行数据位于 `weizhuo/data/`，IP 自动识别主要面向 macOS。小程序、云开发、账号登录、公网和多实例均尚未实现。

英文仓库名称为 `weizhuo`；根目录只保留 Git 元数据、文档、配置与必要开发脚本。`weizhuo/` 子目录包含应用、测试、静态素材和依赖。本机开发聊天服务独立于本仓库，不作为分发组件。

运行数据目录由 Git 忽略；测试预览、截图、私人二维码和缓存不属于源码分发内容。仓库不包含旧路径替身或软链接。
